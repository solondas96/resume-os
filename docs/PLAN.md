# ResumeLabs — Master Plan

Resume intelligence without AI. Client-side React 18 + TypeScript + Vite 6 + Tailwind + Zustand, deployed to GitHub Pages.

## 0. Non-negotiable constraints

1. No AI, LLMs, ML models, embeddings, or external inference APIs. All intelligence is deterministic (curated data, rules, regex, rule-based NLP, scoring formulas). Every suggestion is explainable ("Flagged because…").
2. No backend. 100% client-side. No telemetry, analytics, or runtime network calls beyond the app's own static assets. Deploys to GitHub Pages (`base: './'`).
3. Works offline after first load (PWA service worker, final milestone).
4. Privacy is a feature. Data lives only in the browser (IndexedDB/localStorage). Say so in the UI.
5. Never break existing users. Legacy keys (`resumeos_state_v1`, `resumeos_profiles_v1`, `resumeos_history_v1`, `resumeos_cover_letter_v1`, `resumeos_job_desc_v1`) migrate losslessly on first load, with a backup kept.
6. The tool never invents content. It suggests, highlights, reorders, and guides; the user writes every word.

## 1. Milestone 0 — Known problems

- XSS: markdown output sanitised with DOMPurify; tests cover `<img onerror>` / `<script>`, including the `#view=` share path.
- Image-only PDF: export uses the browser print dialog with A4 `@page` CSS, so text is selectable and extractable.
- Dead code: `src/services/parsing.ts` removed; its skills taxonomy folds into the skills dictionary (Milestone 3).
- README drift: unify on ResumeLabs in UI, package name and docs; keep storage-key migration.

Acceptance: `npm run lint`, `npm run test`, `npm run build` pass; XSS tests pass; exported PDF text extracts with pdf.js and matches the visible content.

## 2. Milestone 1 — Structured resume data model

Structured `Resume` is the source of truth; markdown stays as an editing surface.

- `src/model/resume.ts`: `Resume`, `Section` (experience, education, projects, skills, certifications, custom), items, bullets, `YearMonth`, stable ids.
- `src/model/serialize.ts`: `resumeToMarkdown` / `markdownToResume`, round-trip safe for the supported dialect. Unknown content goes into `custom` sections, never dropped.
- Rendering (preview, PDF, recruiter view) is generated from the model.
- `src/model/migrate.ts`: v1 → v2 with tests using real fixtures from `src/data/rolePresets.ts`.
- Persistence in IndexedDB with localStorage fallback. Store split into slices.
- Undo/redo on the model, separate from named revision snapshots.

Acceptance: all role presets round-trip markdown → model → markdown with no semantic loss; old saved data loads after migration.

## 3. Milestone 2 — Usable by anyone

- First-run welcome: upload resume (PDF/DOCX), start from a role, start blank. Privacy note: "Everything stays in your browser. Nothing is uploaded."
- Import pipeline (`src/import/`), fully in-browser: PDF via pdfjs-dist with positional line reconstruction; DOCX via mammoth; text/Markdown; heading detection by aliases; date-range parser; contact extractor.
- Review screen after import. Low-confidence fields highlighted. Unmatched lines go to an "Unsorted" bucket. Never silently drop text.
- Fixture set of at least 15 varied resumes, tested.
- Form editor as the default; Markdown becomes an "Advanced" toggle. Inline-editable cards, drag-to-reorder (`@dnd-kit`), keyboard accessible, "Present"-aware date pickers, hide/rename sections, pin/hide bullets, visible autosave state.
- Onboarding: 4-step dismissible tour. Empty states explain the next step.

Acceptance: a non-technical user can go from "drop a PDF" to "export a clean PDF" without seeing Markdown.

## 4. Milestone 3 — Intelligence engine (deterministic)

`src/intelligence/` holds pure, framework-free functions. Input: `Resume` and optionally `JobPosting`. Output: typed findings:

```ts
interface Finding {
  id: string;
  rule: string;                       // e.g. 'bullet.no-metric'
  severity: 'info' | 'suggestion' | 'warning' | 'critical';
  category: 'impact' | 'clarity' | 'ats' | 'consistency' | 'length' | 'match' | 'seniority';
  target: { sectionId?: string; itemId?: string; bulletId?: string; field?: string };
  message: string;
  why: string;
  fix?: { label: string; apply: (r: Resume) => Resume };
}
```

4.1 Data assets: skills and titles taxonomy with synonyms (generated by a script in `scripts/`, licence attribution in `ATTRIBUTIONS.md`); action-verb lexicon; weak-phrase map; seniority lexicon.

4.2 Health score (0–100) in five categories: Impact, Clarity, ATS-readiness, Consistency, Length. Rules include missing metrics, weak openers, long bullets, filler phrases, mixed tenses, inconsistent dates, missing contact info, non-standard headings, page length, stale roles. Timeline rules (gaps over 6 months, overlaps) are info-level only.

4.3 Job description matcher: requirement extraction (must-have vs nice-to-have), normalisation via rule-based lemmatisation and alias resolution, evidence strength (strong / moderate / weak / missing), match score weighted toward must-haves, gap list. Replaces the old ATS modal and tailor panel with one Match panel.

4.4 Tailoring (user-driven): duplicate as a linked variant; rank bullets by TF-IDF relevance and offer reorder and cut suggestions; all changes as accept/reject diffs.

4.5 ATS preview: "What applicant tracking software sees": reading-order plain text, detected sections, contact fields, and problem flags.

4.6 Bullet builder: guided composer (intent → verbs → what / how much / how) assembling an XYZ-style bullet; prompts for a missing metric.

4.7 Seniority check: scope and ownership signals against the target level, with the specific missing signal types.

Acceptance: `src/intelligence` at least 90% line coverage; every rule has a positive and a negative test; same input gives same output.

## 5. Milestone 4 — Job hunt

- Applications tracker: company, role, link, status (saved / applied / interview / offer / rejected), dates, notes, linked tailored variant and match score. Board and table views.
- Cover letter as a template from structured data; user writes all prose.
- Export bundle: resume PDF, cover letter PDF, plain-text resume, JSON backup.
- Share link v2: `lz-string` compression, sanitised render, hide phone/email toggle, warning that the link is readable by anyone who has it.
- PWA: service worker, installable, offline.

## 6. Design principles

- Warm-minimal identity (ivory/charcoal, terracotta `#c96442`, Geist). Refine, don't replace.
- The preview is the hero. One primary action per screen (Improve · Match · Export); the rest in the Cmd+K palette.
- Intelligence inline: severity dots beside bullets, with the "why" and fix on click. A compact health ring in the status bar opens the full report.
- Editor left, preview right, one contextual inspector with tabs (Health · Match · Design · History).
- WCAG 2.2 AA contrast in both themes; keyboard navigation; visible focus; `prefers-reduced-motion`.
- Mobile: editor/preview tabs; inspector as a bottom sheet.
- Motion 150–200 ms. Celebrate only real milestones (first export, score ≥ 85).
- Plain, warm, non-judgmental copy.

## 7. Engineering rules

- Milestones in order. At the end of each: lint, test, build; README updated; conventional commit message.
- `src/intelligence/` and `src/model/` stay free of React imports.
- Playwright e2e for the critical paths (import → review → edit → export → ATS preview; paste JD → match → tailor → accept diff).
- Bundle budget: initial JS ≤ 300 KB gzip; lazy-load pdf.js, mammoth, taxonomy, tracker.
- No new runtime network dependencies. Fonts and data self-hosted.
- Justify each new dependency in the commit message.

## 8. Out of scope

AI/LLM features; user accounts; servers or databases; payments; analytics or telemetry; scraping job boards.

## 9. Definition of done

A first-time, non-technical user can: drop in a PDF → confirm parsed sections → see a health score with explained fixes → paste a job description and see met and missed requirements → create a tailored copy with accept/reject → check the ATS preview → export a text-based PDF and cover letter, offline, with nothing leaving the browser.
